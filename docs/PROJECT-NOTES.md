# 项目记录摘要

> 从工程账本（24 条目、22 段复核记录、29 份 gates 证据）压缩而来。目的是让接手者不用读几百 KB 过程文档，也能知道**每个反常设计背后的原因**。完整证据链已随清理移除，本文件是唯一留存。

## 1. 这个项目是怎么来的

| 阶段 | 结论 |
|---|---|
| 立项依据 | 先做了 DSH 0.2.1-rc.5 的宿主能力审计（原生能力对照），确认「设置页必须自绘、无 schema→表单渲染器」后才决定自建而非 fork |
| 为什么不自建 fork | 参考实现 `dsh-prompt-rewriter` 有 3522 行，其中约 1085 行（30.8%）是明确不要的功能；且它没有提示词字段、没有预设概念，fork 后要删掉三成再补两项 |
| 规模 | 最终 index.js ~1030 行 / client.js ~1800 行，注释率 27–42% |

## 2. 关键设计决定（附原因）

| 决定 | 原因 |
|---|---|
| 模型目录走 `ctx.remote.session.modelCatalog()` | 宿主官方投影，自带 4 个失效事件；不读任何 provider 的配置文件，不对任何第三方模型池做特判 |
| 设置读写全走 `ctx.configForms` | 宿主持久化层自带 revision 栅栏、写队列、冲突恢复；不自建 HTTP 设置通道、不直接写 profile 文件 |
| 不 require 任何 `@deepseek-ai/*` 客户端包 | 官方插件开发指南（`cordis-plugin-development/references/practices.md` L35）明令禁止：内部模块无通知变更、组件崩溃会让整个 slot entry 消失 |
| 按钮撤销只做单级 + 依赖原生 Ctrl+Z | `insertText` 底层是「一次独立可撤销编辑」，插件再做多级栈会与编辑器历史打架 |
| 上下文用 JSON 而非标签包裹 | 历史文本无法伪造 JSON 结构，比 `<conversation_context>` 标签转义更彻底 |
| 超时在路由入口用 `AbortSignal.timeout` | 模型调用本身无超时；不接这一层，provider 不响应会让请求永久悬挂 |

## 3. 真机缺陷修复史（都是用户实测暴露的）

| 版本 | 缺陷 | 根因 |
|---|---|---|
| 1.0.1 | 切会话中断改写 | 组件 unmount 时 abort 了请求 → 任务与在途请求提升为模块级 `Map<sessionId>` |
| 1.0.1 | 发送后一直转圈 | 发送后无人收尾在途请求 → 监听 `phase`/空草稿，静默 abort 复位 |
| 1.0.2 | 模型目录加载失败 | 作用域 inject 只声明 `remote`，代码访问 `remote.session` 子路径 |
| 1.0.3 | 每次改写 10–126s | 跟随路由把会话的 `reasoningEffort`(max) 带进改写调用；实测确认上下文**不是**原因（开关对照无差异） |
| 1.0.5 | 审计 S2×3 | parked 重试重放旧 rev（死锁）/ readConfig 漏 effort / 芯片坐标 clipboard↔detect 错配 |
| 1.0.7 | 设置页整页空白 | 渲染期调用未定义函数 `catalogStatus()` → slot entry 被摘除 |
| 1.0.8 | 两列开关没生效、保存条穿模、模型选不了 | CSS 加了但没接进 JSX；`position:sticky` 层叠；换原生 select 后没有加载触发点 |
| 1.0.13 | 模型下拉永久禁用 | `catalog.subscribe` 零调用 → 加载完成不重绘（**独立审计发现**） |
| 1.0.14 | 保存可能半成功 | set 与 unset 分两次写，各带自己的 revision → 合并为单次原子 mutate |

## 4. 两次独立审计的结论（价值最高）

### 4.1 全量审计（7 项，S2×3）

- **parked 死锁**：结果被 CAS 拒后，「重试」永远重放旧 `draftRev`，无 UI 出口，只能刷新。
- **固定模型强度从未生效**：`readConfig` 返回体漏 `reasoningEffort`，设置页写入被静默丢弃。
- **芯片草稿必写回失败**：插件用 clipboard 坐标构造 span，宿主要 detect 坐标（芯片在 detect 投影占 1 字符）。
- 回归样本 R1（失败态跨发送存活）部分通过、R2（失败原因可读）通过、R3/R4 无法验证。

### 4.2 设置页专项审计（7 项全 FAIL）

最严重一条：`catalog.subscribe` 从未被调用 —— 目录加载完成后页面不重绘，下拉永远禁用。**修了之前的「模型选不了」只接了 `load()` 没接订阅**。

审计者最重要的一句判断：

> **闸门全绿不等于通过** —— harness 的假 `unset` 恒返回 true、不模拟 revision 变化、不渲染首帧、不比对 CSS 数值。

这说明了为什么自己写的 harness 会复制自己的盲区，必须换人审计。

## 5. 已知限制

| 限制 | 说明 |
|---|---|
| 命令芯片草稿 | 草稿含 `/` 命令标签时结果可能无法自动写回——宿主不发布这类芯片的坐标换算数据，插件侧无解。成功路径：删掉标签再优化，或重试。`@` 引用标签不受影响 |
| 思考强度被拒 | 固定模型不支持的档位会被宿主拒绝（`UNSUPPORTED_REASONING_EFFORT`）；已实现「丢弃档位按默认强度重试一次」 |
| ≤480px 窄屏 | follow/fixed 高度差约 40px；实测 DSH 设置面板不会窄到此程度，**决定不修** |
| 未验证项 | 原生 select 对越界 value 的具体渲染（修复不依赖该事实）、`data-tone` 的视觉细节（用户截图已确认蓝色生效） |

## 7. 验证方式

```powershell
node --check index.js ; node --check client.js   # 语法
# 行为闸（若保留）：真实环境需自建，验证思路见下
```

项目无 lint / 类型检查 / 构建脚本（纯 JS、无构建）。替代验证 = 语法检查 + 真机操作。真机验证清单：

1. 空草稿不出按钮；有草稿出现
2. 点优化 → 显示「已用 N 秒」→ 结果原位写回 → 可回退
3. 等待中切会话再切回，结果仍在
4. 优化中直接发送，转圈立即消失
5. 设置页：改开关 → 状态行变蓝 → 保存 → 重开仍在
6. 固定模型下拉可点开、换模型后强度回「模型默认」
