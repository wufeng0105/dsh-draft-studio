# 架构与设计决定

> 给接手维护者：**每条反常设计背后的原因**，以及**这些设计是怎么被真机打出来的**。
>
> 如果你只想知道「升级后哪里可能坏」，看 [`HOST-CONTRACT.md`](HOST-CONTRACT.md)；这一页回答的是「为什么代码长这样」。

## 1. 形状

- 纯 JavaScript，**无构建、无 `node_modules`**。依赖由宿主提供。
- `index.js`（宿主半包）：Config schema、模型路由、上下文装配、生成循环、`POST /dsh-draft-studio/refine`。
- `client.js`（浏览器半包）：输入框旁的按钮组、设置页、中英文案。
- 两半通过一条 loopback HTTP 路由通信；请求体只带 `draft` / `sessionId` / `presetId`。

## 2. 术语

| 定为 | 含义 | 容易混的地方 |
|---|---|---|
| 预设 | **一套配置**：完整提示词 + 生效名 + 一颗按钮 | 不单指提示词文本 |
| 生效名 | `nameXxx` 非空则用它，否则回落内置默认名 `OptionA`–`OptionD` | 名字只影响显示，不参与请求 |
| 优化按钮 | 输入框旁的那颗，每套预设一颗，最多四颗 | 不叫「改写按钮」 |
| 编辑门 | 设置页「编辑 / 完成」那个只读开关 | 只管输入权限，不管存取 |
| 降级 | `configForms` 不可用时只渲染一颗按钮、请求不带 `presetId` | 是设计兜底，不是故障 |

## 3. 关键设计决定

| 决定 | 原因 |
|---|---|
| 模型目录走 `ctx.remote.session.modelCatalog()` | 宿主官方投影，自带失效事件；不读任何 provider 配置文件，不对第三方模型池特判 |
| 设置读写全走 `ctx.configForms` | 宿主持久化层自带 revision 栅栏、写队列、冲突恢复；不自建 HTTP 设置通道、不直接写 profile 文件 |
| 不 require 任何 `@deepseek-ai/*` 客户端包 | 官方插件开发规范禁止：内部模块无通知变更、组件崩溃会让整个 slot entry 消失 |
| 撤销只做单级 + 依赖原生 Ctrl+Z | `insertText` 底层是「一次独立可撤销编辑」；再做多级栈会与编辑器历史打架 |
| 上下文用 JSON 而非标签包裹 | 历史文本无法伪造 JSON 结构，比标签转义更彻底 |
| 预设与生效名**不**外置成 JSON 文件 | 外置清单要自定路径、格式、读失败与热更新，还得保证不与 `Config` 的 20 个字段分叉；且文件一旦可写就多出一条「谁能改 system prompt」的写入面。挂在 `Config` 上则由宿主 schema 校验 + `configForms` 的 revision 栅栏免费拿到 |
| 不采用 `storageDomain` 存预设 | `storageDomain` 是**宿主服务**（本仓没有这个词，搜不到是正常的）：它是客户端存储，宿主半包**读不到**。请求在宿主侧选预设文本，存在浏览器里等于每次请求都要把文本回传，正撞「只传标识不传文本」 |
| 超时在路由入口用 `AbortSignal.timeout` | 模型调用本身无超时；不接这一层，provider 不响应会让请求永久悬挂 |
| **故意不声明 `engines.dsh`** | 宿主里 `engines.dsh` 一旦声明就**单独决定**兼容性，不满足时整个 bundle 被跳过、插件从界面整体消失。而 semver 的预发布规则让声明只能逐 rc 元组各写一支，宿主每出一个新 rc 就全部落空。不声明则回落到 peer 检查，本包唯一的 peer 是 `@deepseek-ai/schemastery`（不匹配 `dsh` / `dsh-*` 前缀，被跳过）→ 恒判兼容。代价：失去「宿主太旧就别装」的前置拦截，靠部署后真机发现 |
| 每颗按钮各自一个组件实例 | 每颗需要约 21 个 hook，React 不允许在 `map` 里循环调用；且每颗必须各自持有任务记录，否则两颗共用一个 spinner |
| 任务表配一条模块级通知总线 | 任务表是裸 `Map`，写入发生在一颗按钮的异步回调里。不广播时其余几颗不重绘、仍可点，一点就覆盖在跑那颗的 controller——**静默丢 controller**，spinner 永不结束 |
| 输入框根元素用块级 flex + 28px 高 | 原来用 `inline-flex`，图标无文字时基线落在盒底，整组被顶高；块级 flex 不参与基线，28px 与模型选择器等高 |
| 图标再下移 1.3px | 盒子等高同心后图标仍显高：模型文字含降部字母，墨迹中心比行盒中心低约 2px，而图标是上下对称方块。这是光学差异，布局对不齐，只能补偿 |

## 4. 走过的弯路

都是用户实测暴露的。留着是因为**同一个坑会以新形状再来一次**。

| 版本 | 症状 | 根因 |
|---|---|---|
| 1.0.1 | 切会话中断改写 | 组件 unmount 时 abort 了请求 → 任务与在途请求提升为模块级 `Map<sessionId>` |
| 1.0.1 | 发送后一直转圈 | 发送后无人收尾在途请求 → 监听 `phase` / 空草稿，静默 abort 复位 |
| 1.0.2 | 模型目录加载失败 | 作用域 inject 只声明 `remote`，代码却访问 `remote.session` 子路径 |
| 1.0.3 | 每次改写 10–126s | 跟随路由把会话的 `reasoningEffort`（max）带进改写调用；实测确认上下文**不是**原因 |
| 1.0.5 | 结果被拒后重试无出口；固定模型强度不生效；芯片写回必失败 | parked 重放旧 rev（死锁）；`readConfig` 漏 `reasoningEffort`；芯片坐标 clipboard↔detect 错配 |
| 1.0.7 | 设置页整页空白 | 渲染期调用未定义函数 → slot entry 被摘除 |
| 1.0.8 | 两列开关没生效、保存条穿模、模型选不了 | CSS 加了但没接进 JSX；`position:sticky` 层叠；换原生 select 后没有加载触发点 |
| 1.0.13 | 模型下拉永久禁用 | 目录 store 的订阅从未接上 → 加载完成不重绘 |
| 1.0.14 | 保存可能半成功 | set 与 unset 分两次写，各带自己的 revision → 合并为单次原子 `mutate` |
| 1.1.0 | 点 B 却用了 A 的提示词（规格阶段被拦下，未进真机） | 只改了「选哪套」，没改 `generate` 的取值路径——它仍读 `config.systemPrompt` |
| 1.1.0 | 设置页布局四改才对齐 | 前三次都在调间距；真因是**两行用了两套栅格**（上 2 列带内边距、下 4 列），列边界永远不重合 |
| 1.1.0 | 按钮比模型选择器高 | 见第 3 节最后两行：`inline-flex` 基线 + 文字墨迹中心偏移，两件不同的事叠在一起 |

### 一条贯穿始终的教训

> **闸门全绿不等于通过。**

- 1.0.x 自己写的测试 harness 里，假 `unset` 恒返回 true、不模拟 revision 变化、不渲染首帧、不比对 CSS 数值——**自己写的闸会复制自己的盲区**。
- 1.1.0 更硬的一次：行为判据当时 25/25 全绿，独立复核仍翻出 6 处问题，其中 2 处会让功能失效（跨按钮状态通道缺失、默认文本比对手法依赖一个本机不存在的导入路径）。判据只证明「文本形状对」，证明不了「照它写能写对」。

所以只认两样东西：**当轮重跑的命令**，和**别人能照着复现的反例**。

## 5. 已知限制

| 限制 | 说明 |
|---|---|
| 命令芯片草稿 | **根因在宿主侧**：命令芯片在 detect 投影里占 1 字符，其坐标换算数据宿主不发布给插件，所以插件无法构造能写回的 span。`@` 引用芯片坐标可折算，不受影响。用户看到什么、怎么绕，见 `README.md` 的「边界」 |
| 思考强度被拒 | 宿主对固定模型不支持的档位直接拒绝；插件侧只能丢弃档位、按模型默认强度重试一次。**这是宿主能力边界，不是缺陷** |
| 窄屏 | 设置页六格已加两级断点（<660px 折 3 列、<480px 折单列），但**只在样式层验证过，未实机缩窗确认** |
| 深色主题 | 全部用宿主别名 token，理论上跟随，**未实机切换验证** |
| 未验证项 | 默认文本的逐字节比对、`presetId` 回落与请求体无提示词字段的 curl 行为验收，均未在真机跑过 |

## 6. 契约不变量

> 下面这些是**改代码时不许动**的东西。任何改动碰到其中一条，先停下来重新规划，而不是顺手改掉。
> 每条都绑着一个可执行判据（`npm run check-contract` 或 `npm run check-version`），没有判据的会注明只能人工核。

| # | 不变量 | 判据 |
|---|---|---|
| I1 | 请求体只有 `draft` / `sessionId` / `presetId`；**绝不接受提示词文本** | `check-contract`（伪造 `systemPrompt` 字段，断言送进模型的 system 不变） |
| I2 | 成功响应 7 个字段、失败响应 5 个字段；**失败时 `finish === code`** | `check-contract` |
| I3 | `context.status` 只有六态；`ok` 仅在 `turns > 0` 时出现 | `check-contract` |
| I4 | 失败仍是 HTTP 200 + `ok:false`（405/403/400/503 四个例外除外） | `check-contract` |
| I5 | 按钮四态 `idle / busy / undo / error` 不变 | 人工（`taskReducer` 未导出） |
| I6 | 同一会话同时只跑一个（`RUNNING` 按 `sessionId` 单锁） | 人工 |
| I7 | 设置页「上次改写」的可见性 ≡ 宿主回报过 `context`；**跳过记录 ≠ 清空记录** | `check-contract`（源码级守卫断言）+ 人工 |
| I8 | `package.json` / `CHANGELOG` / git tag 三处版本一致 | `npm run check-version` |

**为什么写在这里而不是 `HOST-CONTRACT.md`**：那份文件是「宿主升级后哪里会坏」的对外清单，末尾自带「管不到什么」的边界声明；内部契约放进去会让两种语义打架。
## 7. 验证方式

没有 lint、类型检查、构建脚本（纯 JS、无构建）。验证分三层，前两层机械、第三层人眼：

```powershell
node --check index.js ; node --check client.js    # 语法
npm run self-check -- -SkipLive -Port <当前端口>   # 清单契约 + 宿主运行时 + 端到端
npm run check-version                              # 版本 / CHANGELOG / tag 一致性
```

真机清单（每次改动后手工过一遍）：

1. 空草稿不出按钮；有草稿出现
2. 点优化 → 显示「已用 N 秒」→ 结果原位写回 → 可回退
3. 等待中切会话再切回，结果仍在
4. 优化中直接发送，转圈立即消失
5. 设置页：改一格 → 状态行变蓝 → 保存 → 重开仍在
6. 六格联动：点「编辑」第 3 格变输入框；改完名，下拉选项与按钮悬停同步变
7. 勾选互斥：取消某一套后，输入框那颗按钮消失，其余紧靠，中间不留空位

**为什么机械层不够**：见第 4 节末尾那条教训。判据只能守住「已知不能犯的错」，未知的错只能靠换一个视角看。
