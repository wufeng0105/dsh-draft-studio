# 提示词优化

**你在输入框里随手打了一句还没想清楚的话，点一下，它就变成 AI 真能照着干的完整指令。**

改完还是草稿，不会替你发出去。不满意就点回去，或者按 Ctrl+Z。

---

## 它解决什么问题

你打字都是边想边写的，比如：

> 帮我写个爬虫抓豆瓣

你自己知道想干什么，但交给 AI 就容易跑偏：抓哪些字段？要不要存成文件？请求太快会不会被封？出错怎么办？这些你没说，它只能猜。于是你得来回问三四轮才说清楚。

点一下这颗按钮，同一句话会变成：

> 用 Python 写一个抓豆瓣电影 Top250 的爬虫，输出片名、评分、简介、链接。要求：遵守 robots.txt，每次请求间隔不少于 2 秒，结果存成 JSON 文件。如果页面结构变化导致解析失败，要明确报错，不能悄悄跳过。<技术栈二选一：requests+BeautifulSoup / Playwright>

目标、限制、输出格式、怎么算做完了——全在里面了。而且它**不会替你拿主意**：你没想好的技术栈，它列出几个候选让你挑，不会自己拍板。

### 为什么值得单独装一个

| | 不装 | 装了 |
|---|---|---|
| 写出来的指令 | 取决于你当时写得多细 | 每次都把目标、限制、输出格式补齐 |
| 来回沟通 | 常常要追问两三回 | 一次说清 |
| 会改动你的原话吗 | —— | 会，但一键就能还原 |

## 它是怎么做的

点下按钮后，它拿你的草稿（可以顺便读一下当前对话最近几轮，用来搞清"刚才说的那个"指什么）发给模型，要求模型只返回改写后的内容，再写回输入框。

- **用哪个模型，你说了算**：跟着当前会话走（连思考强度一起跟随），或者在设置里固定一个。
- **四套预设，每套一颗按钮**：通用 / 编程 / 写作 / 翻译。每套就是一段完整的提示词，你可以直接改——觉得它改得不对味，就去改那段话本身。设置页里可以决定哪几颗按钮出现在输入框（默认四颗全在），也可以给它们改名。
- **不会替你发送**：改完还是草稿。发不发、什么时候发，你决定。

**安装**：DSH 插件页 → 添加插件 → 本地目录，选中这个文件夹。

**卸载**：插件页 → 本插件 → 移除。只想暂时停用，把开关关掉就行，不用卸载。

## 怎么用

### 那颗按钮

草稿非空时才出现，位置在发送按钮左边，**最多四颗，每颗对应一套预设**（通用 / 编程 / 写作 / 翻译）。点哪颗，就用哪套提示词改写。显示哪几颗由设置页决定，默认四颗全显示；取消勾选只是藏起那颗按钮，那套提示词不会丢，重新勾上就回来。

每颗按钮有四种状态：

| 状态 | 你看到什么 | 点它会 |
|---|---|---|
| 空闲 | 一个图标 | 用这套预设开始改写 |
| 进行中 | 「已用 N 秒」 | 取消 |
| 改好了 | 结果已经写回输入框 | 还原成原话 |
| 失败了 | 鼠标悬停看原因 | 重试 |

**一颗在跑，其余几颗会变灰**：同一个对话同一时间只跑一个，免得两颗的结果互相打架。每颗按钮的"还原"和"重试"，只管它自己那次改写。

等待期间你可以继续打字、切到别的对话，甚至直接把草稿发出去：

- 草稿已经变了，结果**不会覆盖**你后来打的字，会留着等你重试；
- 切走再切回来，请求不会断，状态还在；
- 发送之后，转圈会自己停掉。

### 设置页

设置 → 提示词优化：

- **一行六格**（一样宽一样高，外面套一个框）：
  1. **启用**：总开关。
  2. **读取上下文**：要不要读当前对话最近几轮，用来搞清"刚才说的那个"指什么。
  3. **预设下拉**：选中哪套，下面那个大文本框里就是哪套的内容。选项显示的是它当前的名字。
  4. **显示按钮**：这套要不要出现在输入框里。**不需要先点"编辑"**，因为藏一颗按钮不算改内容。全都不勾时，输入框不显示任何按钮，设置页会提示你。
  5. **编辑 / 完成**：默认名字和提示词都是只读的，点它才能改，改完点"完成"。这样做是为了避免你只是点进设置看一眼，就把一套提示词改掉了。**点"编辑"时，第 3 格的下拉会变成一个名字输入框**，就地改名（默认 `OptionA`–`OptionD`，最多 12 个字，留空就用默认名；名字只影响显示，不影响实际请求）。
  6. **默认**：把这一套提示词恢复成插件内置的原版。**不需要先点"编辑"**。
- **提示词编辑**：就是一段完整的提示词。清空后再保存，也等于恢复原版。
- **模型来源**：「跟随会话 / 固定模型」二选一。选固定时多出两个下拉：模型、思考强度。
- **上次改写**（保存按钮上方那一行）：告诉你勾了"读取上下文"到底管不管用——读到了几轮、多少字，或者没读到的具体原因（开关关着 / 拿不到对话 / 这个对话还没有历史 / 被条数或字数上限筛掉了）。只有成功的那次才更新，也不会显示对话内容。
- **底部**：左边显示还有几项没保存，右边是"放弃"和"保存"。

## 配置项

一共 20 个，可以在 `cordis.patch.yml` 的 `config:` 里改，也可以在设置页改。改完立刻生效——每次请求都会重新读配置。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `preset` | `general` | 没指定用哪套时，默认用这套（general / code / writing / translation） |
| `promptGeneral` / `promptCode` / `promptWriting` / `promptTranslation` | 内置文本 | 每套预设的完整提示词 |
| `presetButtons` | 四套全选 | 输入框显示哪几颗按钮（顺序固定）。空数组 = 一颗都不显示 |
| `nameGeneral` / `nameCode` / `nameWriting` / `nameTranslation` | 空（即 `OptionA`–`OptionD`） | 每套显示的名字，最多 12 个字，只影响显示 |
| `contextEnabled` | `true` | 是否读取对话上下文 |
| `modelMode` | `follow` | `follow` 或 `fixed` |
| `provider` / `model` | 空 | 固定模型时选定的服务商和模型 |
| `reasoningEffort` | 空（用模型默认） | 固定模型的思考强度 |
| `maxOutputTokens` | `5000` | 单次输出上限（实际首发还会多留 1500 给思考；顶满时会自动翻倍重试，最多 3 次、封顶 16000） |
| `timeoutMs` | `480000` | 单次请求最长时间，单位毫秒（含内部的翻倍重试，最坏情况 3 次都算在这一个时限里） |
| `contextMaxMessages` / `contextMaxChars` | `8` / `4000` | 读上下文时的条数上限和字数上限 |

## 说在前面的限制

- **带 `/` 命令的草稿**：草稿里如果有一个从 `/` 菜单里选出来的命令标签，改写结果可能写不回去——因为 DSH 没把这东西的位置数据开放给插件。你的原话不会丢，结果也会留着等你重试；把那个标签删掉再点一次就行。`@` 引用别人/别的东西的标签不受影响。
- 手打的 `/xxx` 只是普通文字，不是命令标签，没影响。
- **思考强度被拒**：固定的模型如果不支持你选的那档强度，会自动按该模型的默认强度再试一次——结果正常，只是强度设置没生效。
- **快慢取决于模型和强度**：跟随模式会继承当前对话的强度（对话是 Max 就跑满 Max）。想快想省，固定一个轻量模型或者低强度。
- 最多等 480 秒，超时后草稿不变，可以重试。
- **不做的**：不会自动发送、不做多轮改写、没有模板库、不留历史记录、重启后也不会把上下文找回来。
- **设置服务不可用时会降级**：如果 `configForms` 拿不到（比如你的环境里没装设置基础包），设置页会显示"不可用"，输入框旁**退回只有一颗按钮**，请求也不带预设标识——行为和 1.0.x 完全一样，不会报错。这是故意设计的兜底，不是坏了。

## DSH 升级后跑一下

DSH 每升一次版本，跑这个命令，三十秒内就知道插件还活着没：

```powershell
npm run self-check -- -SkipLive -Port <当前端口>
```

四层检查：源码语法 → 清单契约 → 宿主运行时 → 端到端真打一次接口。哪层失败都会告诉你怎么办，并以退出码 1 结束。只想验证、不想花模型额度，就加 `-SkipLive`。

两个容易踩的点：

- **`--` 不能省**。npm 不会转发不认识的参数。写成 `npm run self-check -SkipLive` 时，npm 只会打一行警告，然后不带参数地执行脚本——等于偷偷真打了一次模型接口。
- **端口要现填**。宿主每次启动都会换端口，去 Web 界面地址栏里看当前那个；脚本内置的三个候选端口不一定对得上。

这个包**故意不声明** `engines.dsh`：一旦声明，宿主遇到不认识的版本时会直接拒绝装载整个插件（不是警告，是不加载）；而不声明时，回落到的那层检查对我们永远判定为兼容。所以升级后插件照常出现，靠上面这节的两条命令确认它还活着。官方库的声明方式要是变了，是另一处常见故障，脚本会直接报出来。

## 源码地图

纯 JavaScript，不用构建、没有 `node_modules`（依赖由宿主提供）。验证方式：`node --check` + `self-check` + 真机跑一遍。

| 文件 | 干什么的 |
|---|---|
| `index.js` | 宿主那一半：配置定义（20 个字段全是热更新）、模型路由三级回退、上下文装配、`resolvePresetKey`（按请求里的 `presetId` 决定用哪套）、`generate`（按结束原因分派 + 预算翻倍重试 + 强度回退）、`POST /dsh-draft-studio/refine` 接口（请求栅栏：必须 POST / Host 必须是本机 / Origin 必须是本机 / Content-Type 必须是 `application/json`；另有 1 MiB 大小上限和超时中断） |
| `client.js` | 浏览器那一半：`createPresetStore`（记住勾选和名字）、`RefineControl` + `RefineButton`（最多四颗按钮，每颗四态）、`insertText` 写回（带草稿版本校验和命令标签位置换算）、一键还原、跨对话的任务记录表、设置页（名称 / 勾选 / 编辑门）、中英文案 |
| `cordis.patch.yml` | 装载声明（一行 insert，entry id 全库唯一） |
| `package.json` | `dsh.bundle.patch` + `dsh.client`；`@deepseek-ai/schemastery` 放在 `peerDependencies` |
| `locale/*.json` | 市场卡片的标题和简介 |

想改提示词文字，看 `index.js` 里的 `PROMPT_BASE` / `PRESETS`；想改交互，看 `client.js` 里的 `RefineControl`；想改模型路由，看 `index.js` 里的 `resolveRoute`；想改设置页控件，看 `client.js` 里的 `SettingsSection`。

**只要动了任何宿主 API，先改 [`docs/HOST-CONTRACT.md`](docs/HOST-CONTRACT.md)**——那里面列了我们依赖的 25 个契约点，以及每个点断了会是什么症状。
